# BeeMind — Stage 1.5

تطبيق Android أصلي يعمل دون اتصال لإنشاء الملاحظات العربية وقراءتها وتعديلها وحذفها. شبكة Masonry فعلية، ومحرر نص طويل، ومسودات محلية لاستعادة الكتابة. لا بيانات تلقائية ولا سمات أو تنبيهات في هذه المرحلة. لا أذونات تشغيل مطلوبة.

## هوية Stage 1.5

نظام **Cosmic × Iridescent Pride** داكن دائمًا: خلفية حبرية بتدرج هادئ في الرئيسية، بطاقات فحمية بإطار محايد، عنوان BeeMind صغير، ولمسة طيف كامل على زر الإنشاء وخط الهوية فقط. إضاءة الإطار مؤقتة أثناء اللمس؛ انتقالات ظهور/اختفاء 180ms تعتمد مقياس حركة Android عبر Compose، دون حركة مستمرة. المحرر والتفاصيل مساحة كتابة مفتوحة، مع حوارات وتغذية راجعة بنفس النظام.

خط **BeeMind Text** يجمع حروف Manrope اللاتينية وTajawal العربية محليًا، بوزنين عادي وعريض، مع اسم مشتق جديد احترامًا لرخصة OFL. المصادر والتراخيص في `licenses/fonts`، وإعادة البناء باستخدام `python3 tools/build_fonts.py` (fonttools 4.61.1). لا تنزيل خطوط في التطبيق. الأيقونة جناح نحلة هندسي واحد بستة ألوان متدرجة على خلفية موحدة، مع Adaptive Icon من API 26 ونسخة monochrome للمشغّلات الداعمة من API 33؛ يشتق Android المظهر القديم من الطبقات نفسها.

توجيه هذه المرحلة يستبدل تعليمات المظهر الفاتح القديمة في PRD وAGENTS؛ لا يغير نطاق الوظائف. لم تتغير قاعدة البيانات أو ViewModels أو المستودع أو مسارات التنقل أو ترتيب ومعاينات النصوص. التحقق على هاتف المالك يظل مطلوبًا، خصوصًا لوحة المفاتيح وTalkBack والتحديث مع الاحتفاظ بالبيانات.

## البناء

- JDK 17، Gradle 8.11.1 (Wrapper مع SHA-256)، AGP 8.9.2.
- Kotlin وCompose compiler 2.1.20، KSP 2.1.20-1.0.32، Compose BOM 2025.04.01، Room 2.7.1.
- `minSdk 26`، `compileSdk/targetSdk 35`، SDK Build Tools 35.0.0. AGP 8.9 يدعم API 35 ويتطلب Gradle 8.11.1 وJDK 17؛ إضافة Compose compiler بنفس إصدار Kotlin. كل الإصدارات مثبتة في `gradle/libs.versions.toml`.
- مراجع التوافق: https://developer.android.com/build/releases/past-releases/agp-8-9-0-release-notes و https://developer.android.com/jetpack/androidx/releases/room#2.7.1 و https://kotlinlang.org/docs/compose-compiler-migration-guide.html .

ثبت Android SDK ثم ضع مساره في `local.properties` (غير متتبع):

```properties
sdk.dir=/your/android-sdk
```

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

فحوص اقتراح إصدارات أحدث فقط (`GradleDependency` و`AndroidGradlePluginVersion`) مستثناة من Lint لأن الإصدارات مثبتة وتُحدّث معًا بعد مراجعة التوافق؛ تنبيه `OldTargetApi` معلوماتي لأن التطبيق يوزّع APK خارج المتجر ويستهدف API 35 المثبت مع الأدوات المختبرة؛ لا تُدّعى مطابقة متطلبات نشر Google Play الحديثة. تبقى فحوص توافق API (`NewApi`) وغيرها فعالة وتُعامل تحذيراتها كأخطاء. ترقية target إلى أحدث منصة تتطلب مراجعة سلوكها واختبارها قبل اعتمادها.

تحتاج أدوات البناء فقط اتصالًا لتنزيل الاعتماديات. التطبيق نفسه بلا إنترنت. اختبارات Robolectric تشغّل Room حقيقيًا واختبارات Compose على JVM، بما فيها إعادة إنشاء Activity. هذا لا يغني عن اختبار لوحة المفاتيح وTalkBack والأداء وإعادة تشغيل هاتف فعلي.

## البنية والبيانات

وحدة `app` واحدة، `data/local` للجداول وDAO والترحيل، و`domain/NotesRepository` لحد البيانات، و`data/RoomNotesRepository` للمعاملات، و`ui/notes` للشاشات وViewModels. `ui/theme/Design.kt` و`ui/components` يحددان الألوان والتدرج والطباعة والأشكال والحالات المشتركة. حقن يدوي عبر المنشئ دون إطار إضافي.

- Room إصدار **2**، مع `MIGRATION_1_2` يضيف `notes` و`editor_drafts` ويحافظ على جدول Stage 0 `app_metadata` ومحتواه. المخططان 1 و2 متتبعان. لا ترحيل مدمر.
- ملاحظة بمعرف UUID ثابت، عنوان اختياري، متن كامل، وتاريخَي إنشاء وتعديل. التعديل يستهدف المحتوى فقط، والحفظ دون تغيير لا يغيّر التاريخ. إعادة المحاولة بنفس ID لا تنشئ نسخة، والحفظ والحذف وتنظيف المسودة معاملات ذرّية.
- الترتيب `createdAt DESC, id ASC` لحسم التعادل بثبات. الرئيسية تقرأ معاينة متن حتى 420 حرفًا وعنوانًا حتى 160 حرفًا، وتستخدم `LazyVerticalStaggeredGrid` بارتفاعات حسب المحتوى. تتحول لعمود واحد عند ضيق العرض أو تكبير الخط. التفاصيل تقرأ النص الكامل في كتل Lazy لا تُسقط أي حرف. القراءة من SQLite نفسها مجزأة داخل معاملة متسقة لتجاوز حد CursorWindow مع اليوميات الكبيرة؛ المعاينات تُقاس بمحارف Unicode لا بوحدات UTF-16.
- المحرر يستخدم `TextFieldState` داخل ViewModel للاحتفاظ بالنص خلال إعادة التكوين. التنقل يحفظ UUID فقط، ولا يُحفظ النص الطويل في Bundle. اختبار الواجهة يفحص حجم الحالة المحفوظة مع يوميات طويلة.
- المسودة سجل منفصل، وليست ملاحظة محفوظة أو بطاقة في الشبكة. تُكتب بعد هدوء الكتابة 250ms وتُطلب كتابتها أيضًا عند الانتقال للخلفية، ويظهر تأكيد المسودة بعد نجاح الكتابة. تتاح «متابعة مسودة» في الرئيسية. الحفظ يحولها لملاحظة بمعاملة واحدة؛ التجاهل يحذف المسودة فقط. الخروج مع تعديل يعرض حفظ/متابعة/تجاهل.
- إيقاف العملية قسرًا أو انقطاع الطاقة قبل اكتمال الكتابة قد يفقد آخر إدخال لم يُؤكّد كمسودة؛ لا تعتمد على المسودة بدل زر الحفظ. لا يُدّعى ضمان حفظ كل ضغطة قبل Force stop.
- معرّف الملاحظة هدف ثابت لروابط جداول السمات المستقبلية. لا تُنفّذ السمات أو واجهاتها الآن.

معرف التطبيق ثابت: `com.beemind.personal`. النسخ الاحتياطي السحابي ونقل بيانات التطبيق مستبعدان. حذف التطبيق قد يحذف بياناته المحلية؛ لا أداة تصدير في V1.

## GitHub Actions وAPK

من تبويب **Actions → BeeMind Android → تشغيل ناجح → Artifacts** حمّل ZIP باسم:
`BeeMind-0.2.5-build-N-persistent-test` أو `BeeMind-0.2.5-build-N-TEMPORARY-NON-UPGRADE-GUARANTEED`.

يتضمن APK وSHA-256 وبصمة شهادة التوقيع. الرفع بعد نجاح التجميع وUnit Tests وLint وفحص التوقيع فقط. مدة الاحتفاظ 30 يومًا. يعمل عند push وpull request وبـ **Run workflow** يدويًا بعد وصول workflow للفرع الافتراضي. تشغيل fork PR لا يحصل على أسرار التوقيع وينتج مؤقتًا. لا تستخدم APK الخاص به كتحديث معتمد.

`versionName=0.2.5` و`versionCode=github.run_number`؛ لا تعِد إنشاء workflow بعداده من الصفر دون ضبط رمز أعلى من آخر نسخة موزعة. إعادة تشغيل run نفسه تعيد رقم البناء ذاته؛ لتوزيع تحديث جديد شغّل Run workflow جديدًا. محليًا الرمز الافتراضي 1 ويمكن تمرير `BEEMIND_VERSION_CODE`.

## إعداد مفتاح اختبار ثابت — على جهازك الموثوق فقط

إذا لم تضف الأسرار الأربعة ينتج APK مؤقت بمفتاح debug خاص ببيئة البناء. **تحديثه لاحقًا فوق النسخة نفسها غير مضمون**، بما في ذلك أول انتقال للمفتاح الثابت. استخدم ملاحظات اختبار قابلة للفقد فقط إلى حين اعتماد التوقيع الثابت. تأجيل إعداد المفتاح قرار المالك ولا يمنع بناء Stage 1. لا تُغيّر المفتاح بعد اعتماد أول نسخة ثابتة.

1. أنشئ مفتاحًا خارج المستودع باستخدام JDK (يسألك عن كلمة مرور؛ لا ترسلها في محادثة):

   ```sh
   keytool -genkeypair -keystore beemind-test.jks -storetype JKS -alias beemind-test -keyalg RSA -keysize 3072 -validity 10000
   ```

   عند طلب كلمة مرور المفتاح، اضغط Enter لاستخدام كلمة مرور المخزن نفسها. احتفظ بالمفتاح وكلمة المرور في نسختين احتياطيتين آمنتين خارج Git. فقدهما قد يمنع تحديث التطبيق مع الاحتفاظ ببياناته.

2. حوّل الملف إلى Base64 (Linux):

   ```sh
   base64 -w 0 beemind-test.jks > beemind-test.base64.txt
   ```

   على macOS: `base64 -i beemind-test.jks | tr -d '\n' > beemind-test.base64.txt`. الملف الناتج سر أيضًا.

3. افتح المستودع → **Settings → Secrets and variables → Actions → New repository secret** وأضف:

   | الاسم | القيمة |
   |---|---|
   | `BEEMIND_KEYSTORE_BASE64` | محتوى ملف Base64 كاملًا |
   | `BEEMIND_STORE_PASSWORD` | كلمة مرور المخزن |
   | `BEEMIND_KEY_ALIAS` | `beemind-test` |
   | `BEEMIND_KEY_PASSWORD` | كلمة مرور المفتاح (نفس كلمة مرور المخزن بالخطوة السابقة) |

4. شغّل **Actions → BeeMind Android → Run workflow**. يجب أن يحمل Artifact اللاحقة `persistent-test`. تحقق من تطابق بصمة شهادة SHA-256 في ملف certificate مع كل إصدار ثابت. امسح ملف Base64 المؤقت بأمان من جهازك بعد الحفظ. لا ترفع أي مفتاح أو كلمة مرور إلى Git.
5. ثبات التحديث يتطلب المفتاح نفسه ومعرف التطبيق نفسه ورقم بناء أعلى. اختبار ترحيل SQLite آليًا لا يثبت إمكانية تثبيت APK بمفتاح مختلف فوق النسخة السابقة. اختبار تحديث التطبيق على الهاتف مع الاحتفاظ بالبيانات لم يُجرَ. لا تحذف نسخة تحتوي بيانات لاختبار تحديث.

## اختبارات Stage 1

```sh
./gradlew --no-daemon :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

في Stage 1 السابق، اجتاز التحقق المحلي 21 اختبارًا دون فشل أو تجاوز، ونجح `assembleDebug` و`lintDebug` (بلا ملاحظات) باستخدام JDK 17. ما زال اختبار الهاتف الفعلي مطلوبًا.

تشمل الاختبارات: عنوان فقط/نص فقط، رفض الفراغ، تعديل دون تغيير الإنشاء، حفظ دون تغيير، حفظ متزامن بنفس المعرّف، تدفق الإنشاء والحذف، ثبات الترتيب، نص عربي طويل وإعادة فتح قاعدة البيانات، استرجاع المسودة، ترحيل فعلي من مخطط Stage 0 مع بيانات محفوظة وفحص سلامة SQLite، وتجربة Compose للحفظ والرجوع والتأكيد والحذف وإعادة إنشاء Activity. صور اختبار الواجهة والتقارير تُرفع كـ `BeeMind-validation-build-N` منفصل عن APK. بيانات الاختبارات لا تُضاف إلى تطبيق المستخدم.

## تحقق Stage 1.5

نجح `:app:assembleDebug :app:testDebugUnitTest :app:lintDebug` باستخدام JDK 17؛ **23 اختبارًا دون فشل أو تجاوز**، منها 5 اختبارات تجربة Compose عبر Robolectric API 28، وLint بلا ملاحظات. فُحصت صور الرئيسية والبطاقة أثناء الضغط والمحرر والتفاصيل والحالة الفارغة وحوارات الخروج والحذف، بعرض 393dp، والمحرر بعرض 320dp وخط 130%. تُنتج الاختبارات أيضًا الأيقونة الملونة والأحادية بمقاسي 48 و192px. الصور وتقارير الاختبارات تُرفق في Artifact التحقق.

أفضت المراجعة إلى رفع تباين العناوين وتصحيح لون الحالة الفارغة وتنقيح الجناح بخلايا هندسية تُحاكي تعريق جناح النحلة. التباين المحسوب للنص الأساسي فوق البطاقات **15.17:1** وللنص الثانوي **8.46:1**. لا تغيير في المخطط أو DAO أو Repository أو ViewModels أو منطق المسودات والتواريخ؛ تغطية Stage 1 بقيت فعالة.

هذه مراجعة عرض Android عبر Robolectric، وليست تجربة مشغّل أو لوحة مفاتيح أو TalkBack على هاتف حقيقي. لا جهاز متصل أو محاكي Android يعمل في البيئة. لم يُختبر التحديث فوق APK سابق ببياناته؛ التوقيع المؤقت في CI يمنع ضمان ذلك. لا تحذف تثبيتًا يحوي ملاحظات مهمة لتجاوز اختلاف التوقيع.

## اختبار هاتف Stage 1.5 — ست خطوات

1. افحص الخلفية الداكنة والعنوان الصغير والحالة الفارغة، حتى عندما يكون نظام الهاتف فاتحًا.
2. أنشئ ملاحظات متفاوتة الطول وتحقق من وضوح البطاقات وتفاوت ارتفاعاتها وترتيبها.
3. اضغط بطاقة ضغطة قصيرة ثم أطول قليلًا وافحص الإضاءة القزحية المؤقتة وسلاسة فتح التفاصيل.
4. افتح المحرر واكتب نصًا عربيًا طويلًا مختلطًا بالإنجليزية؛ افحص الالتفاف والتحديد والمؤشر مع لوحة المفاتيح.
5. كبّر الخط ودوّر الهاتف أثناء التحرير؛ تحقق من المسودة والحفظ والرجوع وتأكيد الحذف وبقاء النص بعد إعادة الفتح.
6. افحص جناح الأيقونة في المشغّل بأحجام وأقنعة مختلفة، ثم راقب سلاسة التمرير والتنقل.

التوقف عند Stage 1.5 إلزامي حتى اختبار المالك للـAPK وطلب مرحلة لاحقة صراحةً.
